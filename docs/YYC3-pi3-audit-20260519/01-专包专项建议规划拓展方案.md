## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| CLI 测试修复涉及第三方 API mock | 中 | 延迟 Phase A | 优先修复纯逻辑测试，API 测试用 MSW mock |
| repository 统一需 GitHub 仓库操作 | 低 | 延迟 Phase D | 提前确认最终仓库名 |
| effects 测试需要浏览器环境 | 中 | 延迟 Phase B | 使用 vitest jsdom + @testing-library/react |
| changesets 集成改动较大 | 中 | 延迟 Phase E | 可先手动管理版本，后续自动化 |

## 七、总结

### 核心发现

1. **架构优秀**: 三层依赖拓扑、TypeScript strict、ESM 优先，技术选型合理
2. **标杆包突出**: @yyc3/i18n-core 以零依赖、443 测试、八件套文档树立了标准
3. **3 包阻塞发包**: mcp-servers/motion/cli 文档闭环严重缺失
4. **CLI 质量隐患**: 39 测试失败 + typecheck 跳过，需优先修复
5. **品牌一致性不足**: repository URL 有 3 种写法，部分包缺少关键字段
